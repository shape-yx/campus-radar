# 校园雷达 · 机会画布

> **产品名称：校园雷达（campus-radar）** —— 把 26 条校园机会摊在一张画布上。
> 视觉语言照 Awwwards 收录的 bleibtgleich'26「Work」演示视频实测还原。

**在线地址**：https://shape-yx.github.io/campus-radar/
**零依赖 · 零构建 · 无后端**：全部是原生 HTML/CSS/JS，双击 `index.html` 即可运行

---

## 〇、它解决什么问题

珠海科技学院的活动信息散在公众号、班级群、社团群和海报里，学生面对的真实困难不是"信息太少"，而是三个：

1. **看不到全貌** —— 不知道自己手里到底有几件事、哪些已经错过。
2. **不知道先后** —— 截止日期是文字，不读一遍就感受不到紧迫程度。
3. **不知道能不能参加** —— "限大一""需 8 小时志愿时长"这类条件藏在正文里，看完才发现不符合。

校园雷达的处理方式是把**时间与条件从文字里搬到画面上**：26 条机会摊成一张可旋转的球面画布，
**截止越近的卡片越大越亮**，一眼扫过就知道先处理哪个；设定自己的年级与每周可投入时间后，
每条都会给出「适合你 / 需先确认 / 暂不符合」**并说明理由**，而不是只给一个结论。

**界面范式**：从"五个页面 + 顶部导航"改成"一个画布 + 四种排布"。

| | 常见的列表式 | 这一版（机会画布） |
|---|---|---|
| 结构 | 五个页面，靠路由切换 | **一个画布**，内容不离开视线 |
| 条目 | 列表行，尺寸一致 | **画布上的物件**，有坐标、大小、层级、倾斜 |
| 排序 | 下拉框选排序方式 | **换排布**：球面 / 散落 / 网格 / 时间轴 |
| 详情 | 跳转详情页，列表位置丢失 | **右侧推入面板**，画布留在后面，关掉回到原位 |
| 紧急度 | 一个文字标记 | **卡片本身变大变亮**，散开时肉眼就能看出优先级 |

## 一、为什么把"截止时间"做成卡片的物理属性

列表式界面里，"什么时候截止"只是**一个字段**；在这一版里它是**卡片的物理属性**：

- 球面上，越急的卡片越靠近正中、越大越亮，越不急的越往两侧、越小越暗
- 散落时按紧急度从中心向外铺开，尺寸分 4 档
- 时间轴把"还有几天"直接换成横向距离，拖动就是移动时间

不用读文字，扫一眼就知道先处理哪个。这正是参考视频里那个页面的手法：**让信息本身承担版式**。

## 二、从参考视频量出来的规格

把 Awwwards 页面上的演示视频下载下来（27 秒 / 1600×1200 / 30fps），抽 12 帧做像素分析：

| 卡片底色 | `#000000` 纯黑 | `rgb(0,0,0)` ✅ |
| 卡片圆角 | 0（全直角） | `0px` ✅ |
| 胶囊圆角 | `999px` | `999px` ✅ |
| 栅格缝隙 | 11px | `11px` ✅ |

| 栅格 | 2 列满宽 | 2 列满宽 ✅ |

## 三、四种排布，默认是「所有项目」球面

顶栏四个入口 + 一个「我的」：

```
[01] 所有项目   [02] 散落   [03] 网格   [04] 时间轴   [05] 我的
```

### 01 所有项目 · 球面（默认，照参考视频 3—5 秒）

26 条信息贴在**一个看不见的球体表面**上：

- 竖向按纬度分 5 层、横向按经度绕圈，卡片朝球心方向倾斜（越靠边缘倾得越多）
- 透视投影后由 z 决定三件事：**近大远小**（缩放 0.47 → 0.79）、**近亮远暗**（透明度 0.16 → 0.70）、**层级前后**
- 球体缓慢自转（约 30 秒一圈）
- **鼠标拖动可任意转动**，松手后带受控惯性继续滑行（速度上限 1.6e-3 rad/ms，不会失控）
- **滚轮缩放**球体半径
- 卡片尺寸与球半径解耦：半径变化时卡片保持可读，不会被拉得看不清

### 02 散落 / 03 网格 / 04 时间轴

- **散落**——按紧急度从画布中心向外铺开，带旋转与 4 档尺寸。用"槽位网格 + 固定抖动"保证**不重叠**
- **网格**——吸附归位成参考视频里那个 2 列，旋转全部归零，行高按该行最高卡片对齐
- **时间轴**——**可拖动的横向时间条**：卡片按截止日沿一条时间线排开，日期刻度随拖动一起平移；横排冲突时自动右推避免叠在一起

双击画布空白可在 散落 ↔ 网格 之间切换；`1`/`2`/`3`/`4` 切换四种排布。

### 右侧缩放条（桌面端）

窗口右缘有一条竖排缩放条：上下是加减按钮，中间是可拖动的滑轨（50%–200%），
底部方框显示当前比例、点击可复位。缩放比例存在本机，刷新后保留。
快捷键 `+` / `−`，或 `Ctrl/⌘ + 滚轮`。

- 缩放的是画布内容本身（`transform: scale`），所以球面、网格、时间轴都跟着放大缩小
- **缩放中心锁在球体中心**：`transform-origin` 由球面布局算出球心的像素坐标写入
  （不写死 `50% 50%` —— canvas 的高宽会随排布与筛选变化，用百分比会与球心错开）；
  任何改变 canvas 尺寸的地方都会重新同步一次
- **手势位移会按缩放比折算**：放大到 200% 时拖 200px 只转半圈，不会"跑得比手快"
- 容器默认 `pointer-events: none`，只有按钮和滑轨可交互 —— 否则这条浮在右缘的控件会挡住画布拖动
- 窄屏（≤900px）自动隐藏

### 05 我的

右侧推入面板（沿用当前实现）：四类统计 + 收藏 / 报名 / 发布 / 忽略四组明细 + 画像设置 + 备份导出。

## 四、主要功能（业务逻辑与原版一致）

| 功能 | 说明 |
|---|---|
| **我能不能参加** | 设定年级与每周可投入时间，每条给出「适合你 / 需先确认 / 暂不符合」并说明原因 |
| **信息变更合并** | 同一件事的多条通知并进主条目，面板里用时间线呈现「原始通知 → 后续通知」并给出结论 |
| **筛选** | 时间 / 类别 / 来源 / 仅我能参加 / 含降权 + 关键词搜索；筛选后卡片平滑移出画布外 |
| **详情** | 右侧面板三个标签：这是什么 / 我能不能参加 / 原文信息（材料未写的显示「未注明」） |
| **收藏 / 标记报名 / 不感兴趣** | 存在本机，「我的」面板里可查看与撤销 |
| **发布（需口令）** | 默认隐藏，输入管理员口令（初始 `radar2026`）后可发布，发布的内容立刻落到画布上 |
| **我的** | 四类统计 + 收藏 / 报名 / 发布 / 忽略四组明细，可改画像、导出导入备份 |

**快捷键**：`1`/`2`/`3` 切换排布，`/` 聚焦搜索，`Esc` 关闭面板。

**判定基准时间**为材料标注的考核当日 `2026-09-19 14:00`。

## 五、自主设计的实用与创新内容

材料里没有现成答案，以下是本项目**自己想出来并实现**的部分：

### 1. 把"我能不能参加"从结论变成带理由的判定

多数活动汇总只写"限大一""需志愿时长"。这里把条件拆成**结构化字段**（年级下限、可投入时间、
是否限本校、材料是否明确），再逐条读出一个判定，并且**必须给出理由**：

```
适合你           与你的时间安排（每周 6 小时）不冲突
需先确认         材料未注明面向年级；你的年级不在明确范围内
暂不符合         与你的年级不符（要求大一，你是大三）
```

**为什么这么做**：只给结论的判定没法让人信任，也没法让人自己复核。理由是可验证的。

### 2. 信息变更的合并：同一件事被通知多次，只占一张卡片

同一条活动可能先发"原定 9 月 20 日"，后发"改到 9 月 21 日"。这里把多条通知**并进一个主条目**，
在详情页用时间线呈现「原始通知 → 后续通知 → 结论」，并标注"这件事被通知了 2 次，以最新一条为准"。
画布上始终只有一张卡片，不会因为改期就出现两条。

### 3. 位置与形变全部由 JS 算出的四种排布

四种排布不是四套 CSS，而是**四个布局算法**（都写在 `assets/app.js` 里，无第三方库）：

- **球面**：真三维投影。卡片按球面坐标放置，用 `rotateY(经度) rotateX(纬度)` 让法线朝球外，
  形变（左右收窄、上下压短、背面缩小）全部由 `perspective` 投影算出，不是手搓拉伸
- **散落**：槽位网格 + 伪随机抖动，**用分离轴定理（OBB）保证 0 对重叠**（含旋转卡片）
- **网格**：吸附归位，行高按该行最高卡片对齐
- **时间轴**：按截止日铺开，冲突时自动右推；可横向拖动 = 拖动时间

### 4. 零后端实现"发布带图"

考核要求"核心体验不依赖后端"。发布图片通常是第一个被砍的功能，这里用**前端压缩成 dataURL**
实现：等比缩到最长边 720px、JPEG 0.82、超 260KB 自动降质 ——
**实测 1600×1200 / 2.4MB 的 PNG 压到 16KB**，可以直接存进 localStorage。

### 5. 把参考视频"量"出来，而不是凭感觉调

参考站的手法是用像素分析反推的：下载演示视频抽帧，逐帧扫描颜色与深色块包围盒，
量出页面色 `#94a04b`、卡片 `#000000`、圆角 0、间距 11px、卡片宽只占视口 **4%—7%**、
边缘卡片会被压成 **2—11px 的细条**等参数，再照着实现（详见第二节）。

### 6. 70 项自查脚本

`check.js` 用无头 Chrome + CDP 跑 **70 项**检查，覆盖业务结论与画布机制，
并且**多次在自查里发现真 bug**（见第六节）—— 例如"卡片透明度被 CSS 过渡吃掉，整屏卡片卡在 0.008、
等于全都看不见"这个问题，就是自查发现的。

### 自查

```bash
node check.js http://127.0.0.1:8801/index.html ./shots
```

无头 Chrome + CDP，**70 项**检查。除了业务结论（状态判定、适配判定、变更合并、口令门），
重点是**画布机制本身**：

- 散落态 22 张卡片**用旋转后的 OBB 相交判断：0 对重叠**，且全部落在画布内
- 散落态确实带旋转、尺寸分 4 档（紧急度可见）
- 网格态吸附成 2 列、旋转全部归零、两列左右交替
- 时间轴有 5 条日期刻度
- 详情从侧栏推入且画布仍在 DOM 里（没有跳页）
- 布局已落定时卡片必须是实心的（`opacity ≥ 0.5`）
- **球面**：22 张全部参与、缩放与透明度都有纵深跨度、横向铺开 800px+、自动自转、拖动同时改变俯仰与经度、惯性速度不超过上限
- **层级**：卡片 z-index 必须低于侧栏（回归断言），并逐点采样确认侧栏内容没被卡片遮挡
- **时间轴**：卡片互不重叠、纵向不出画布、拖动可平移时间线、日期刻度跟着走、拖动不会误开详情
- **缩放条**：贴住窗口右边、竖排滑轨、拖动可放大/缩小、点击复位、缩放后手势位移按比例折算；
  并校验**缩放原点就是球体中心**（偏离 ≤2px）、**绕球心缩放时原点在屏幕上漂移 ≤1px**

## 七、开发中修掉的几个真问题

前两个是"断言算过、画面没到"的同类问题，第三个是算法错误：

1. **测试拍到飞行途中的卡片**——初始布局是固定 `sleep` 后截图的，结果拍到半透明、位置错乱的卡片。
   断言查的是 JS 计算出的最终坐标，那只证明"算对了"，没证明"画到了"。
   **修法**：加"布局已落定"标志（`__App.settled`），测试轮询它而不是猜等待时间，并补一条"卡片必须实心"的断言。
2. **用 AABB 判断旋转卡片的重叠**——把旋转后的包围盒相交误判成重叠，报了 36 对假重叠。
   **修法**：改用分离轴定理（OBB 相交）判断，真实结果是 0 对。
3. **散落布局纵向溢出**——槽位网格按列数算，没校验行高，22 张卡需要 1038px 而舞台只有 706px，
   卡片被压到画布外。而且那条"放不下就回退"的判断条件写反了。
   **修法**：改为逐列数试算，挑"行列都装得下"的最小列数；确实放不下时才统一缩小卡片。

4. **`const` 挡住了一次重新赋值**（最难查的一个）——加"缩放折算"时写了 `dx /= z`，
   而 `dx` 是 `const`，赋值直接抛 `Assignment to constant variable`，
   **整个拖动分支从这一行开始失效**：球面转不动、时间轴拖不动、连拖动后的点击都被吞。
   报错只出现在事件监听器里，页面上看不到任何提示。
   **修法**：把 `dx`/`dy` 改成 `let`。教训是"在一个已经很长的处理器里插一行赋值"
   要先看清变量的声明方式。

5. **指针捕获把点击"吃"掉了**（真实的交互 bug）——为了让拖动在指针移出画布后仍可控，
   原先一按下就调了 `setPointerCapture`。但捕获会把"指针底下是谁"从真实元素改成捕获元素，
   结果：① click 不再派发给卡片 → 点卡片打不开详情；② 卡片上的 pointermove 被算成
   "落在画布上" → 连轻点卡片都被当成拖动吞掉。
   **修法**：认清 stage 本来就覆盖整个画布，拖动靠 stage 自身的 move/up 就能完成，
   **完全不需要捕获**。把三种手势（球面旋转 / 时间轴平移 / 点击打开）重写成一套状态机，
   只用位移阈值（6px）区分拖动与点击，并在拖动结束时吞掉紧随的那一次 click。

5. **时间轴轨道一层层叠加**——刻度容器只清理了内部的线与标签，没删容器本身，
   于是每次重绘都多叠一层；`querySelector` 取到的永远是最早那个 offset=0 的旧容器，
   表现为"拖动后刻度不动"。**修法**：清理时把容器本身也一起删掉。

6. **球面卡片盖住了侧栏**——球面用 `1000 + z` 给卡片排序做纵深，前排卡片能到 1300 多，
   而侧栏只有 `z-index: 1001`，结果点开卡片后有 6 张卡片压在详情上、字都看不清。
   **修法**：建立明确的层级约定（卡片 10…410 / 悬停 500 / 遮罩 1000 / 侧栏 1001 / 吐司 2000），
   把卡片层级整体压到侧栏之下，并加一条回归断言：除比较 z-index 外，
   还用 `elementFromPoint` 在侧栏范围内采样 45 个点，确认没有任何一点的最上层元素是卡片。

另外修掉一个逻辑遗漏：`layout()` 只把坐标写进 CSS 变量，没写回对象，导致自查脚本读到全 0 的坐标。

## 八、已知限制

- 纯静态站点：数据只存在浏览器 localStorage，发布的内容只有本机可见；管理员口令是**本机口令**，不是真正的安全边界
- 散落态的抖动是伪随机的（用槽位坐标做种子），所以同一批数据每次布局一致，不会每次刷新都换位置
- 顶栏使用珠海科技学院校徽图片，仅用于表明作品归属院校；**本作品不是学校官方产品**，页内 26 条信息均为考核模拟材料
- 材料里的 26 条信息本身没有配图，所以卡片默认用"条目编号"做视觉占位（参考视频里是作品截图）；
  发布页支持自带配图（前端压缩成 dataURL），卡片与详情页都会显示
- 发布页的配图只存在本机浏览器：本站无服务器，别人打开在线作品看不到你在本机发布的图片
