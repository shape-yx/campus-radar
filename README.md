# 校园雷达 · 橄榄栅格版（campus-radar-v2）

> 版式与配色**照 Awwwards 收录的 bleibtgleich'26「Work」演示视频实测还原**：橄榄黄绿底 + 纯黑卡片 + 细缝栅格 + 全直角 + 等宽小字。

这是 `campus-radar` 的**设计实验版**：数据层与判定逻辑一字未改，只重做表现层。正式的考核交付仍是上一版 [campus-radar](https://github.com/shape-yx/campus-radar)。

## 〇、还原依据：从视频帧量出来的数

我把 Awwwards 那个页面上的演示视频（27 秒 / 1600×1200 / 30fps）下载下来，抽出 12 帧做了像素分析，量出以下规格：

| 项 | 视频实测 | 本实现 | 状态 |
|---|---|---|---|
| 页面底色 | `#94a04b` 橄榄黄绿 | `rgb(148,160,75)` | ✅ 一致 |
| 卡片底色 | `#000000` 纯黑 | `rgb(0,0,0)` | ✅ 一致 |
| 栅格缝隙 | 竖向 11px / 横向 10px | `gap: 11px` | ✅ 一致 |
| 内容外边距 | 10px | `padding: 10px` | ✅ 一致 |
| 卡片圆角 | 0（全直角） | `border-radius: 0` | ✅ 一致 |
| 栅格列数 | 2 列，满宽 | 2 列，满宽 | ✅ 一致 |
| 卡片高度 | 首行约 274px | `min-height: 240px` | ✅ 接近 |
| 元信息栏 | 贴卡片底边，`[Case]` 胶囊 + 等宽小字 | `.card__meta` + `.pill` | ✅ 一致 |
| 右上角角标 | 深色胶囊 `Work` | `.chip-now` 显示当前区块名 | ✅ 一致 |
| 页脚大字 | `bleibt`（左）/ `gleich`（右），橄榄色 | `校园` / `雷达`，`rgba(0,0,0,.30)` | ✅ 一致 |

**测量方法**：用 Swift + AVFoundation 抽帧，再用 CoreGraphics 逐像素扫描 —— 找出橄榄色像素的包围盒得到视口边界（949×528，16:9），再按行/列扫描橄榄色的连续区间得到缝隙宽度与列宽。所以上面的数字是量出来的，不是目测的。

**一处刻意没照搬**：视频里页脚那行大字固定在视口底部，卡片滚动时会**从大字上面压过去**。那种"卡片压字"的层叠效果需要把大字做成 fixed / sticky 并处理 z-index，在信息密集的列表里容易挡住最后几行内容。我保留了同样的巨橄榄大字，但让它待在正常文档流里，不做层叠 —— 观感接近，不会牺牲可用性。

## 一、视觉系统

```
页面底 #94a04b（橄榄黄绿）  ／  卡片 #000000（纯黑）
卡片内文字 #f2f0ea  ／  次级 #9aa06a  ／  胶囊底 #111111
强调色 #b4232a（只在紧急标记上用）
```

- **"缝"就是底色**：容器留 10px 外边距、卡片之间留 11px 间隙，橄榄色从缝里透出来形成网格
- **全直角**：卡片、输入框一律 `border-radius: 0`；只有**胶囊**（分类标签、状态标签、按钮、右上角角标）用 `999px`
- **卡片结构 = 黑色方块 + 媒体居中 + 元信息栏压底**：元信息栏左边是 `[分类]` 胶囊加标题，右边是等宽的状态与截止标记
- **等宽小字承载所有元信息**：编号、时间、地点、标签、计数统一 `ui-monospace`，字号 9.5—11px，字距 0.08em
- **深色模式**：把橄榄换成深橄榄 `#3a4020`，卡片仍是黑，同一套逻辑

## 一、参考站做了什么，我取了哪几条

我把参考站的结构读了一遍，提炼出六条可迁移的手法：

| 手法 | 参考站的表现 | 本项目的落地 |
|---|---|---|
| **编号导航** | `[1 Home] [2 Work] [3 Contact]`，页码本身就是内容 | 顶栏导航改为 `[1] 今天 / [2] 索引 / [3] 时间轴 / [4] 发布 / [5] 我的`，当前项反白 |
| **巨型编辑式标题** | 段落标题每个词独占一行、极大字号 | 首屏「今天 / 值得看的 / 校园机会」三行堆叠，字号 `clamp(2.6rem, 9vw, 7rem)`，偶数行转灰形成节奏 |
| **索引 + 标签成对** | 标题旁配 `24 / 26`、`Case / Shot` 分类标签 | 页头右侧显示 `22 ／ 22 条` 这样的索引计数；分类与标签用等宽小字跟在标题下 |
| **细线分栏** | 1px 线分割区块，左标签 + 右内容 | 全站栅格由 1px 线构成：统计条、索引行、事实栏、时间轴、定义列表 |
| **等宽技术标注** | 数字与元信息一律等宽 | 所有标签、编号、时间、计数统一 `ui-monospace`，数字用 `tabular-nums` 对齐 |
| **方块按钮 + 计数角标** | 细线方框、右下角挂 `+0` | 按钮改为等宽大写方框，悬停反白为黑底；自检面板显示 `6 / 6` 计数 |

**没取的一条**：它的信息密度。那是作品集（一屏一张图），这是信息工具（新生要在一屏内扫完截止时间、地点、条件）。照搬"巨型字 + 大留白"会把首屏信息量砍掉一半，与"帮助同学发现、理解、参与"直接冲突。所以巨型标题只用在**首屏和页头**，列表与详情仍是紧凑的细线栅格。

## 二、视觉系统

```
纸白 #f3f1ec   /   墨黑 #0d0d0d   /   细线 #0d0d0d · 弱线 #c9c4b8   /   强调 #b4232a
```

- **近黑白为主**：底色是"纸"，文字是"墨"，深色模式直接对调，强调色贯穿两种模式
- **只有一个强调色**：取自校徽红的 `#b4232a`，只用于"当前 / 紧急 / 缺失"标记。实测首页只有 10 个元素用到它
- **状态不用彩色药丸**：改为等宽大写 + 1px 边框的文字标记（`可报名` / `明天截止` / `暂不符合`），选中态才反白
- **数字全部等宽并表格化对齐**：编号、时间、计数、百分比在视觉上成列

字号层级：

| 用途 | 字号 |
|---|---|
| 首屏巨型标题 | `clamp(2.6rem, 9vw, 7rem)` |
| 页头标题 | `clamp(2.4rem, 7.2vw, 5.6rem)` |
| 区块标题 | `clamp(1.3rem, 2.6vw, 2rem)` |
| 索引项标题 | `clamp(1.05rem, 2vw, 1.45rem)` |
| 等宽标签 | `10—11px`，字距 `0.1em`，大写 |

## 四、怎么运行

### 本地（推荐看效果）

零依赖、零构建，起一个静态服务器即可：

```bash
cd campus-radar-v2
python3 -m http.server 8801
# 浏览器打开 http://127.0.0.1:8801/index.html
```

双击 `index.html` 用 `file://` 打开同样能跑（无外部请求、无后端）。

### 自查

```bash
node check.js http://127.0.0.1:8801/index.html ./shots
```

用 Chrome DevTools Protocol 驱动无头 Chrome，跑 **52 项**检查并出截图。它不只看渲染，还断言两类东西：

- **功能结论**：9 月 18 日已开始的直播必须是「已开始」而不是「进行中」；大一新生看「限大二及以上」必须判为暂不符合；训练营必须取到更新后的地点（实验楼 A402）
- **版式真的生效**（照视频实测值逐条断言）：页面底色是否为 `rgb(148,160,75)`、卡片是否为纯黑、缝隙是否为 11px、栅格是否为 2 列、卡片圆角是否为 0、元信息栏与胶囊是否到位、页脚大字是否为巨橄榄色

## 五、与原版的差异（只列结构，业务未动）

```
campus-radar-v2/
├── index.html              入口（编号导航 + 校徽品牌区）
├── assets/
│   ├── data.js             ← 复用原版，仅 storageKey 改为 campus-radar-v2
│   ├── logic.js            ← 原版一字未改（状态判定 / 适配判定 / 可信度分级）
│   ├── store.js            本地存储、用户发布、收藏举报
│   ├── views.js            【新】runtime：命名空间、参考时间、标记体系、记录行组件
│   ├── screens.js          【新】六个屏幕：今天 / 索引 / 时间轴 / 详情 / 发布 / 我的
│   ├── main.js             【新】壳层：路由、事件、发布、导出、主题
│   ├── editorial.css       【新】编辑式设计系统（替换 theme.css + radar.css）
│   └── img/                校徽 1x / 2x
├── check.js                51 项自查（无第三方依赖）
└── README.md
```

**为什么把 runtime 与屏幕分开**：原版把两者混在 `views.js` 里，700 多行时还能读，改版后行数上升，分开后"共享组件"与"具体页面"边界清楚，改一处不会牵连另一处。

**数据隔离**：`storageKey` 改为 `campus-radar-v2`，与上一版的收藏、发布、口令完全隔离，两个版本可以在同一个浏览器里各跑各的。

## 六、已知限制

- 本次只重写了表现层，业务逻辑沿用原版；原版里已删除的"我替用户写的总结"（`oneLine` / `mustKnow` / `actions`）在新版同样不存在，界面只呈现材料字段
- 顶栏使用珠海科技学院校徽图片，仅用于表明作品归属院校；**本作品不是学校官方产品**，页内 26 条信息均为考核模拟材料
- 纯静态站点：数据只存在浏览器 localStorage，发布的内容只有本机可见，口令是"本机口令"而非真正的安全边界
- 编辑式版式牺牲了原版的一些"圆角卡片亲和感"，换取更强的版面秩序；如果你更看重首屏信息密度，原版 `campus-radar` 更合适

## 七、后续可以做什么

1. **把巨型标题做成"滚动变量字"**：参考站用 GSAP 做字号随滚动插值，原生的 `scroll-driven animations` 现在也能做到，可以让标题在滚动中从 7rem 缩到 2rem
2. **索引行的悬停预览**：鼠标悬停某条时，右侧浮出该条的时间地点摘要，减少一次跳转
3. **筛选结果的"胶片条"视图**：参考站有 Cards / Sphere 两种视图切换，可以加一个"只看时间轴"的视图，直接复用已有的时间轴组件
4. **字体系统升级**：现在用系统等宽字体；若允许外链，换成一套真正的编辑排版字体（如 Neue Haas + 一款等宽）会更接近参考站气质
