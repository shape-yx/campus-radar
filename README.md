# 校园雷达 · 机会画布（campus-radar-v2）

> 26 条校园机会摊在一个画布上：**先散开看见全貌与紧急度，再按排布方式吸附归位**。
> 视觉语言照 Awwwards 收录的 bleibtgleich'26「Work」演示视频实测还原。

这是 `campus-radar` 的**重新设计版**——不是换配色，是换界面范式。数据层与判定逻辑一字未改。
正式的考核交付仍是上一版 [campus-radar](https://github.com/shape-yx/campus-radar)。

---

## 一、界面范式换了什么

| | 上一版（campus-radar） | 这一版（机会画布） |
|---|---|---|
| 结构 | 五个页面 + 顶部导航，靠路由切换 | **一个画布**，内容不离开视线 |
| 条目 | 列表行 / 卡片，尺寸一致 | **画布上的物件**，有坐标、大小、层级、旋转 |
| 排序 | 下拉框选排序方式 | **换排布**：散落 / 网格 / 时间轴 |
| 详情 | 跳转到详情页，列表位置丢失 | **右侧推入面板**，画布留在后面，关掉即回到原位 |
| 紧急度 | 一个文字标记 | **卡片本身变大变亮**，散开时肉眼就能看出优先级 |
| 我的 / 发布 | 独立页面 | 同样是侧栏面板，随时可退回画布 |

**为什么这样改**：原来的结构里，"什么时候截止"是一个字段；现在它是**卡片的物理属性**。
散落态下，最急的事占据中心且最大，越不急越小越暗、越靠外 —— 不用读文字，扫一眼就知道先处理哪个。
这正是参考视频里那个页面的手法：让信息本身承担版式。

## 二、从参考视频量出来的规格

把 Awwwards 页面上的演示视频下载下来（27 秒 / 1600×1200 / 30fps），抽 12 帧做像素分析：

| 项 | 视频实测 | 本实现 |
|---|---|---|
| 页面底色 | `#94a04b` 橄榄黄绿 | `rgb(148,160,75)` ✅ |
| 卡片底色 | `#000000` 纯黑 | `rgb(0,0,0)` ✅ |
| 卡片圆角 | 0（全直角） | `0px` ✅ |
| 胶囊圆角 | `999px` | `999px` ✅ |
| 栅格缝隙 | 11px | `11px` ✅ |
| 内容外边距 | 10px | `10px` ✅ |
| 栅格 | 2 列满宽 | 2 列满宽 ✅ |
| 元信息 | 贴卡片底边，等宽小字 | `.card__foot` ✅ |
| 页脚大字 | `bleibt`/`gleich` 巨橄榄字 | `校园`/`雷达` ✅ |

**测量方法**：Swift + AVFoundation 抽帧 → CoreGraphics 逐像素扫描 → 用橄榄色像素的包围盒定出视口（949×528），再按行列扫描橄榄色连续区间得到缝隙宽度与列宽。上面的数字是量出来的。

## 三、四种排布，默认是「所有项目」球面

顶栏四个入口 + 一个「我的」：

```
[01] 所有项目   [02] 散落   [03] 网格   [04] 时间轴   [05] 我的
```

### 01 所有项目 · 球面（默认，照参考视频 3—5 秒）

26 条信息贴在**一个看不见的球体表面**上：

- 竖向按纬度分 5 层、横向按经度绕圈，卡片朝球心方向倾斜（越靠边缘倾得越多）
- 透视投影后由 z 决定三件事：**近大远小**（缩放 0.47 → 0.79）、**近亮远暗**（透明度 0.16 → 0.70）、**层级前后**
- 球体缓慢自转（约 30 秒一圈）
- **鼠标拖动可任意转动**，松手后带受控惯性继续滑行（速度上限 1.6e-3 rad/ms，不会失控）
- **滚轮缩放**球体半径
- 卡片尺寸与球半径解耦：半径变化时卡片保持可读，不会被拉得看不清

### 02 散落 / 03 网格 / 04 时间轴

- **散落**——按紧急度从画布中心向外铺开，带旋转与 4 档尺寸。用"槽位网格 + 固定抖动"保证**不重叠**
- **网格**——吸附归位成参考视频里那个 2 列，旋转全部归零，行高按该行最高卡片对齐
- **时间轴**——横向按报名截止排开，顶部日期刻度，按天分道

双击画布空白可在 散落 ↔ 网格 之间切换；`1`/`2`/`3`/`4` 切换四种排布。

### 05 我的

右侧推入面板（沿用当前实现）：四类统计 + 收藏 / 报名 / 发布 / 忽略四组明细 + 画像设置 + 备份导出。

## 四、主要功能（业务逻辑与原版一致）

| 功能 | 说明 |
|---|---|
| **我能不能参加** | 设定年级与每周可投入时间，每条给出「适合你 / 需先确认 / 暂不符合」并说明原因 |
| **信息变更合并** | 同一件事的多条通知并进主条目，面板里用时间线呈现「原始通知 → 后续通知」并给出结论 |
| **筛选** | 时间 / 类别 / 来源 / 仅我能参加 / 含降权 + 关键词搜索；筛选后卡片平滑移出画布外 |
| **详情** | 右侧面板三个标签：这是什么 / 我能不能参加 / 原文信息（材料未写的显示「未注明」） |
| **收藏 / 标记报名 / 不感兴趣** | 存在本机，「我的」面板里可查看与撤销 |
| **发布（需口令）** | 默认隐藏，输入管理员口令（初始 `radar2026`）后可发布，发布的内容立刻落到画布上 |
| **我的** | 四类统计 + 收藏 / 报名 / 发布 / 忽略四组明细，可改画像、导出导入备份 |

**快捷键**：`1`/`2`/`3` 切换排布，`/` 聚焦搜索，`Esc` 关闭面板。

**判定基准时间**为材料标注的考核当日 `2026-09-19 14:00`。

## 五、怎么运行

零依赖、零构建：

```bash
cd campus-radar-v2
python3 -m http.server 8801
# 打开 http://127.0.0.1:8801/index.html
```

双击 `index.html` 用 `file://` 打开同样能跑（无外部请求、无后端）。

### 自查

```bash
node check.js http://127.0.0.1:8801/index.html ./shots
```

无头 Chrome + CDP，**54 项**检查。除了业务结论（状态判定、适配判定、变更合并、口令门），
重点是**画布机制本身**：

- 散落态 22 张卡片**用旋转后的 OBB 相交判断：0 对重叠**，且全部落在画布内
- 散落态确实带旋转、尺寸分 4 档（紧急度可见）
- 网格态吸附成 2 列、旋转全部归零、两列左右交替
- 时间轴有 5 条日期刻度
- 详情从侧栏推入且画布仍在 DOM 里（没有跳页）
- 布局已落定时卡片必须是实心的（`opacity ≥ 0.5`）
- **球面**：22 张全部参与、缩放与透明度都有纵深跨度、横向铺开 800px+、自动自转、拖动同时改变俯仰与经度、惯性速度不超过上限
- **层级**：卡片 z-index 必须低于侧栏（回归断言），并逐点采样确认侧栏内容没被卡片遮挡

## 六、开发中修掉的三个真问题

前两个是"断言算过、画面没到"的同类问题，第三个是算法错误：

1. **测试拍到飞行途中的卡片**——初始布局是固定 `sleep` 后截图的，结果拍到半透明、位置错乱的卡片。
   断言查的是 JS 计算出的最终坐标，那只证明"算对了"，没证明"画到了"。
   **修法**：加"布局已落定"标志（`__App.settled`），测试轮询它而不是猜等待时间，并补一条"卡片必须实心"的断言。
2. **用 AABB 判断旋转卡片的重叠**——把旋转后的包围盒相交误判成重叠，报了 36 对假重叠。
   **修法**：改用分离轴定理（OBB 相交）判断，真实结果是 0 对。
3. **散落布局纵向溢出**——槽位网格按列数算，没校验行高，22 张卡需要 1038px 而舞台只有 706px，
   卡片被压到画布外。而且那条"放不下就回退"的判断条件写反了。
   **修法**：改为逐列数试算，挑"行列都装得下"的最小列数；确实放不下时才统一缩小卡片。

4. **球面卡片盖住了侧栏**——球面用 `1000 + z` 给卡片排序做纵深，前排卡片能到 1300 多，
   而侧栏只有 `z-index: 1001`，结果点开卡片后有 6 张卡片压在详情上、字都看不清。
   **修法**：建立明确的层级约定（卡片 10…410 / 悬停 500 / 遮罩 1000 / 侧栏 1001 / 吐司 2000），
   把卡片层级整体压到侧栏之下，并加一条回归断言：除比较 z-index 外，
   还用 `elementFromPoint` 在侧栏范围内采样 45 个点，确认没有任何一点的最上层元素是卡片。

另外修掉一个逻辑遗漏：`layout()` 只把坐标写进 CSS 变量，没写回对象，导致自查脚本读到全 0 的坐标。

## 七、已知限制

- 纯静态站点：数据只存在浏览器 localStorage，发布的内容只有本机可见；管理员口令是**本机口令**，不是真正的安全边界
- 散落态的抖动是伪随机的（用槽位坐标做种子），所以同一批数据每次布局一致，不会每次刷新都换位置
- 顶栏使用珠海科技学院校徽图片，仅用于表明作品归属院校；**本作品不是学校官方产品**，页内 26 条信息均为考核模拟材料
- 卡片目前用"条目编号"做视觉占位（参考视频里是作品截图），因为材料里没有配图

## 八、下一步想做的

1. **拖动重排**：散落态支持用鼠标拖着卡片换位置，位置存进 localStorage —— 让"画布"真的可编辑
2. **卡片连线**：把"同一件事的多条通知"用细线连起来，画布上直接看出哪几条是一伙的
3. **按批次的入场动画**：现在所有卡片同时归位，可以改成按紧急度错峰入场，节奏更接近参考视频
